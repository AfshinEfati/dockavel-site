PROJECT WORKFLOW

Run project commands without memorizing Docker

Dockavel can install a global dockavel command and short terminal aliases. Project metadata still chooses the correct PHP or Node runtime and working directory, but daily commands can now be as short as ds my-api.

CURRENTGlobal CLIProject-aware

Install the global CLI

The interactive ./setup.sh flow offers shortcut installation. You can also install or refresh it manually:

bashone-time install
./dockavel shortcuts:install

Dockavel creates managed symlinks in ~/.local/bin. If that directory is not already in PATH, Dockavel can add one managed block to Bash or Zsh startup configuration and prints the exact reload command.

●
No command overwrite

If a shortcut name already belongs to another file or command, Dockavel leaves it untouched and reports the conflict.

How runtime routing works

Shortcuts do not bypass project metadata. For a Laravel project with:

.dockavel.ymlLaravel
name: "booking-api"
type: "laravel"
path: "booking-api"
php: "8.5"
node: true

the command:

Dockavelshort form
da booking-api migrate

routes to php85 with working directory /var/www/booking-api. Its low-level intent is equivalent to:

Composelow level
docker compose exec -w /var/www/booking-api php85 php artisan migrate

Shell behavior

For Laravel projects, ds opens the configured PHP runtime. For Node projects it opens the shared Node runtime.

bashshell
ds legacy-api   # php82 when metadata says php: "8.2"
ds booking-api  # php85 when metadata says php: "8.5"
ds frontend     # node for a Node project

Safety and validation

  • The configured runtime must be enabled and running.
  • The project directory must still exist on the host.
  • The project path must be visible inside the selected runtime before execution.
  • artisan is rejected for Node projects.
  • npm is rejected when Node is not enabled for the selected Laravel project.
  • Shortcut installation never overwrites an existing command or file.
●
Stale Docker bind mounts

If the project exists on the host but is not visible inside the runtime, Dockavel stops before running the command. Restarting Docker Desktop can resolve a stale WSL bind mount when the host path is otherwise correct.

Shortcut management

bashmanage
dockavel shortcuts:list
dockavel shortcuts:install
dockavel shortcuts:remove

shortcuts:remove removes only symlinks managed by the current Dockavel checkout. It leaves the ~/.local/bin PATH entry untouched because that directory may contain other user commands.

WORKFLOW پروژه

اجرای دستورهای پروژه بدون حفظ کردن Docker

Dockavel می‌تواند دستور global با نام dockavel و shortcutهای کوتاه ترمینال نصب کند. metadata پروژه همچنان runtime درست PHP یا Node و مسیر پروژه را انتخاب می‌کند، اما کار روزمره حالا می‌تواند به کوتاهی ds my-api باشد.

فعالGlobal CLIProject-aware

نصب Global CLI

در اجرای تعاملی ./setup.sh نصب shortcutها پیشنهاد می‌شود. هر زمان هم می‌توانی آن را دستی نصب یا refresh کنی:

bashنصب یک‌باره
./dockavel shortcuts:install

Dockavel symlinkهای مدیریت‌شده را داخل ~/.local/bin ایجاد می‌کند. اگر این مسیر داخل PATH نباشد، Dockavel می‌تواند یک block مشخص و idempotent به startup config مربوط به Bash یا Zsh اضافه کند و دستور reload دقیق را نمایش دهد.

●
بدون overwrite

اگر نام یک shortcut از قبل متعلق به فایل یا command دیگری باشد، Dockavel به آن دست نمی‌زند و conflict را گزارش می‌کند.

Runtime چطور انتخاب می‌شود؟

Shortcutها metadata پروژه را دور نمی‌زنند. برای پروژه Laravel زیر:

.dockavel.ymlLaravel
name: "booking-api"
type: "laravel"
path: "booking-api"
php: "8.5"
node: true

این دستور:

Dockavelفرم کوتاه
da booking-api migrate

به php85 و مسیر /var/www/booking-api route می‌شود و از نظر هدف معادل این دستور سطح پایین است:

Composeسطح پایین
docker compose exec -w /var/www/booking-api php85 php artisan migrate

رفتار Shell

برای پروژه Laravel، ds وارد PHP runtime ثبت‌شده می‌شود. برای پروژه Node وارد shared Node runtime می‌شود.

bashshell
ds legacy-api   # php82 اگر php: "8.2"
ds booking-api  # php85 اگر php: "8.5"
ds frontend     # node برای پروژه Node

Validation و ایمنی

  • runtime موردنیاز باید فعال و running باشد.
  • پوشه پروژه باید روی host وجود داشته باشد.
  • قبل از اجرا مسیر پروژه باید داخل runtime قابل مشاهده باشد.
  • artisan روی پروژه Node رد می‌شود.
  • اگر Node برای Laravel فعال نباشد، npm رد می‌شود.
  • نصب shortcut هیچ command یا فایل موجودی را overwrite نمی‌کند.
●
Bind mount قدیمی Docker

اگر پروژه روی host باشد ولی داخل runtime دیده نشود، Dockavel قبل از اجرای command متوقف می‌شود. اگر path صحیح باشد، restart کردن Docker Desktop می‌تواند stale WSL bind mount را برطرف کند.

مدیریت Shortcutها

bashمدیریت
dockavel shortcuts:list
dockavel shortcuts:install
dockavel shortcuts:remove

shortcuts:remove فقط symlinkهایی را حذف می‌کند که توسط همین checkout مدیریت می‌شوند. entry مربوط به ~/.local/bin در PATH باقی می‌ماند چون ممکن است commandهای دیگری هم در آن مسیر وجود داشته باشند.
