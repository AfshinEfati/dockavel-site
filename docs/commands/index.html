PROJECT WORKFLOW

Run commands in the right runtime automatically

Registered project metadata now routes everyday commands to the correct PHP or Node runtime and working directory. You no longer need to remember Compose service names or manually cd inside a container.

CURRENTProject-awareNo container-name guessing

Commands

CommandPurpose
./dockavel shell <project>Open Bash in the project runtime and project directory
./dockavel artisan <project> [args...]Run php artisan in the project's configured PHP runtime
./dockavel composer <project> [args...]Run Composer in the project's configured PHP runtime
./dockavel npm <project> [args...]Run npm in the shared Node runtime for Node-enabled projects

Examples

bashdaily workflow
./dockavel shell booking-api
./dockavel artisan booking-api migrate
./dockavel artisan booking-api queue:work
./dockavel composer booking-api install
./dockavel composer booking-api update laravel/framework
./dockavel npm booking-api install
./dockavel npm frontend run dev

How runtime routing works

Dockavel reads the registered project's .dockavel.yml. A Laravel project with:

.dockavel.ymlLaravel
name: "booking-api"
type: "laravel"
path: "booking-api"
php: "8.5"
node: true

routes PHP commands to php85 with the working directory /var/www/booking-api. The command:

Dockavelproject-aware
./dockavel artisan booking-api migrate

is equivalent in intent to the longer low-level Compose form:

Composelow level
docker compose exec -w /var/www/booking-api php85 php artisan migrate

Shell behavior

For Laravel projects, shell opens the project's configured PHP runtime. For Node projects it opens the shared Node runtime.

bashshell
./dockavel shell legacy-api   # php82 when metadata says php: "8.2"
./dockavel shell booking-api  # php85 when metadata says php: "8.5"
./dockavel shell frontend     # node for a Node project

npm on Laravel projects

A Laravel project can use npm only when its metadata has node: true. Enable or disable that flag through ./dockavel project:edit.

Project selectors

The same registered-project selector used by Project Manager is reused here. A project can be addressed by its Dockavel name, relative project path or local domain when that selector is unambiguous.

Safety and validation

  • The configured runtime must be enabled in COMPOSE_PROFILES.
  • The runtime container must be running.
  • The project directory must still exist on the host.
  • The project path must be visible inside the selected runtime before Dockavel launches the requested command.
  • artisan is rejected for Node projects.
  • npm is rejected when Node is not enabled for the selected Laravel project.
●
Stale Docker bind mounts

If the project exists on the host but is not visible inside the runtime, Dockavel stops before running the command and points you toward the projects bind mount. On Docker Desktop, restarting Docker can resolve a stale WSL bind mount.

Arguments are passed through

Everything after the project selector is forwarded to the underlying tool without wrapping it in an extra shell.

bashexamples
./dockavel artisan api migrate --force
./dockavel composer api install --no-interaction
./dockavel npm frontend run build -- --mode production

WORKFLOW پروژه

اجرای دستورها در runtime درست، به‌صورت خودکار

Dockavel حالا با استفاده از metadata پروژه، دستورهای روزمره را داخل PHP یا Node runtime درست و در مسیر همان پروژه اجرا می‌کند. دیگر لازم نیست اسم serviceهای Compose یا مسیر داخل container را حفظ کنی.

فعالProject-awareبدون حدس container name

دستورها

دستورکاربرد
./dockavel shell <project>باز کردن Bash داخل runtime و مسیر پروژه
./dockavel artisan <project> [args...]اجرای php artisan داخل PHP runtime ثبت‌شده پروژه
./dockavel composer <project> [args...]اجرای Composer داخل PHP runtime پروژه
./dockavel npm <project> [args...]اجرای npm داخل Node مشترک برای پروژه‌هایی که Node دارند

مثال‌ها

bashکار روزمره
./dockavel shell booking-api
./dockavel artisan booking-api migrate
./dockavel artisan booking-api queue:work
./dockavel composer booking-api install
./dockavel composer booking-api update laravel/framework
./dockavel npm booking-api install
./dockavel npm frontend run dev

انتخاب runtime چطور انجام می‌شود؟

Dockavel فایل .dockavel.yml پروژه ثبت‌شده را می‌خواند. مثلاً:

.dockavel.ymlLaravel
name: "booking-api"
type: "laravel"
path: "booking-api"
php: "8.5"
node: true

باعث می‌شود دستورهای PHP داخل php85 و در مسیر /var/www/booking-api اجرا شوند. بنابراین:

Dockavelproject-aware
./dockavel artisan booking-api migrate

از نظر هدف معادل دستور طولانی زیر است:

Composeسطح پایین
docker compose exec -w /var/www/booking-api php85 php artisan migrate

رفتار shell

برای پروژه Laravel، دستور shell وارد PHP runtime ثبت‌شده می‌شود. برای پروژه Node وارد runtime مشترک Node می‌شود.

bashshell
./dockavel shell legacy-api   # php82 اگر php: "8.2"
./dockavel shell booking-api  # php85 اگر php: "8.5"
./dockavel shell frontend     # node برای پروژه Node

npm برای پروژه Laravel

پروژه Laravel فقط وقتی می‌تواند از دستور npm استفاده کند که در metadata مقدار node: true داشته باشد. این مقدار با ./dockavel project:edit قابل تغییر است.

انتخاب پروژه

همان selector مربوط به Project Manager استفاده می‌شود. در صورت یکتا بودن می‌توان پروژه را با name، مسیر نسبی داخل projects/ یا domain محلی انتخاب کرد.

Validation و ایمنی

  • runtime موردنیاز باید در COMPOSE_PROFILES فعال باشد.
  • کانتینر runtime باید در حال اجرا باشد.
  • پوشه پروژه باید روی host وجود داشته باشد.
  • قبل از اجرای دستور، مسیر پروژه باید داخل runtime انتخاب‌شده قابل مشاهده باشد.
  • اجرای artisan روی پروژه Node رد می‌شود.
  • اگر Node برای پروژه Laravel فعال نباشد، اجرای npm رد می‌شود.
●
Bind mount قدیمی Docker

اگر پروژه روی host وجود داشته باشد ولی داخل runtime دیده نشود، Dockavel قبل از اجرای دستور متوقف می‌شود و مشکل mount را اعلام می‌کند. در Docker Desktop گاهی restart کردن Docker مشکل stale WSL bind mount را برطرف می‌کند.

ارسال مستقیم argumentها

هر چیزی بعد از نام پروژه بدون shell اضافه به ابزار اصلی ارسال می‌شود.

bashمثال
./dockavel artisan api migrate --force
./dockavel composer api install --no-interaction
./dockavel npm frontend run build -- --mode production
