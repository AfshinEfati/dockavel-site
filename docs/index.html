GETTING STARTED

Dockavel at a glance

Dockavel is a lightweight, multi-project local development environment for Laravel and Node.js. One shared Docker Compose stack can run several PHP versions, databases and services while Nginx routes each project to the correct runtime.

CURRENTLaravel + Node.jsDocker ComposeWSL2 friendly

What Dockavel solves

Multiple PHP versions

Run PHP 8.2, 8.3, 8.4 and 8.5 side by side instead of duplicating an entire stack for each project.

Project-aware routing

Register local projects and let Dockavel generate and validate their Nginx configuration.

Regional source presets

Use Official, IranServer, Runflare, China or custom download endpoints with no hidden registry fallback.

Read-only diagnostics

Check Docker, stack health, source reachability and common network failures before rebuilding anything.

Requirements

  • Docker Engine or Docker Desktop
  • Docker Compose v2 via docker compose
  • Bash and an interactive terminal
  • Port 80 available for the Dockavel Nginx gateway
●
Windows

Using Dockavel inside WSL2 is recommended. Docker Desktop with WSL integration works well for this setup.

Install

bashclone + setup
git clone https://github.com/AfshinEfati/dockavel.git
cd dockavel
chmod +x setup.sh dockavel
./setup.sh

The interactive installer creates .env from .env.example when needed, validates the Compose configuration, and asks you to choose only the parts of the stack you need.

Installer choices

  1. Download source preset
  2. PHP runtimes
  3. MySQL and/or PostgreSQL
  4. Redis and Node.js
  5. phpMyAdmin and/or pgAdmin
  6. Whether to build and start immediately
setup result.env
COMPOSE_PROFILES=php82,php85,mysql,postgres,redis,node,mysql-ui

Build and start

When you choose “Build and start”, setup performs the equivalent of:

bashcompose
docker compose pull --ignore-buildable
docker compose up -d --build

The PHP and Node services are built locally from public upstream images, so --ignore-buildable prevents Compose from treating them like prebuilt Dockavel images.

First checks

./dockavel doctorenvironment + stack
./dockavel source:testdownload endpoints
./dockavel project:addregister a project
./dockavel project:listregistered projects

Architecture

routingshared stack
legacy.local   -> nginx:80 -> php82:9000
api.local      -> nginx:80 -> php85:9000
frontend.local -> nginx:80 -> node:3000

shared: mysql | postgres | redis | node
optional UI: phpMyAdmin | pgAdmin

Incremental changes

You do not need to destroy the stack to add a service. Re-run ./setup.sh, keep the current selections, and add the new profile. Compose reuses existing images, build cache, named volumes and unchanged containers whenever possible.

✓
Persistent data stays intact

Running setup again does not remove the MySQL, PostgreSQL or pgAdmin named volumes.

Build و Start

اگر Build and start را انتخاب کنی، رفتار setup معادل این دستورات است:

bashcompose
docker compose pull --ignore-buildable

PHP و Node به‌صورت local از imageهای عمومی upstream build می‌شوند؛ بنابراین --ignore-buildable اجازه نمی‌دهد Compose دنبال image آماده Dockavel بگردد.

تغییر مرحله‌ای استک

برای اضافه کردن سرویس جدید لازم نیست استک را پاک کنی. دوباره ./setup.sh را اجرا کن، انتخاب‌های قبلی را نگه دار و profile جدید را اضافه کن. Compose تا جای ممکن imageها، build cache، volumeها و containerهای بدون تغییر را reuse می‌کند.

داده‌های persistent باقی می‌مانند

اجرای دوباره setup، volumeهای MySQL، PostgreSQL یا pgAdmin را حذف نمی‌کند.
