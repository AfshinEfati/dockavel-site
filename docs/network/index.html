NETWORK-AWARE

Explicit sources, useful diagnostics

Dockavel treats network access as part of the development environment. Source presets keep image and package downloads on a known route, while Doctor and source:test help identify failures without silently changing configuration.

Source preset rule

✓
No hidden fallback

If IranServer is selected, Dockavel intentionally uses the IranServer endpoints configured for that preset. It does not silently retry Docker Hub or GHCR behind the user's back.

Custom endpoints

Custom mode lets you explicitly define the Docker library and namespace prefixes, Debian and Debian security mirrors, Composer repository, npm registry and npm strict-SSL behavior. Values are written to .env.

Doctor

bashread-only
./dockavel doctor

Doctor currently checks:

System

Docker CLI, Docker daemon, Docker Compose, WSL detection, .env and port 80 ownership.

Sources

Selected preset, Docker registry, Debian mirror, Debian security, Composer and npm.

Network detail

HTTP status, response time and remote IP for configured endpoints.

Stack

Enabled services, running state and container health when a healthcheck exists.

i
Docker registry HTTP 401 can be healthy

A registry /v2/ endpoint may require authentication. Dockavel treats 401 and 403 as proof that the endpoint itself is reachable.

IPv4 route hint

If the default connection fails, Doctor performs a read-only IPv4 retry. When IPv4 works, the output calls that out so you can distinguish a broken default/IPv6 path from a completely unreachable source.

source:test

bashconfigured endpoints only
./dockavel source:test

This is the fast source-only check. It uses the endpoints currently configured in .env, does not select or rewrite a preset, and is useful before a large pull/build on unstable or restricted networks.

Failure descriptions

Network-level failures are classified with useful labels such as DNS resolution failure, TCP connection failure, timeout, TLS handshake failure, too many redirects, empty response and connection reset.

●
Diagnostics do not repair

Doctor and source:test do not change DNS, mirrors, Docker configuration, containers, profiles or the hosts file.

Custom endpoints

در حالت Custom می‌توانی Docker library/namespace prefix، mirrorهای Debian و security، Composer repository، npm registry و strict-SSL را صریحاً تعریف کنی. مقادیر در .env ذخیره می‌شوند.

Doctor

bashread-only
./dockavel doctor

Doctor این بخش‌ها را بررسی می‌کند:

System

Docker CLI، daemon، Compose، تشخیص WSL، فایل .env و مالک پورت 80.

Sources

preset انتخاب‌شده، Docker registry، Debian، Debian security، Composer و npm.

جزئیات شبکه

HTTP status، زمان پاسخ و IP مقصد برای endpointهای تنظیم‌شده.

Stack

سرویس‌های فعال، وضعیت running و health container در صورت وجود healthcheck.

i
HTTP 401 رجیستری می‌تواند سالم باشد

endpoint /v2/ بعضی registryها authentication می‌خواهد. Dockavel پاسخ 401 یا 403 را نشانه reachable بودن endpoint در نظر می‌گیرد.

تشخیص مسیر IPv4

اگر اتصال پیش‌فرض fail شود، Doctor یک retry فقط با IPv4 انجام می‌دهد. اگر IPv4 جواب بدهد، خروجی مشخص می‌کند که احتمالاً default/IPv6 route خراب است، نه اینکه source کاملاً unreachable باشد.

source:test

bashconfigured endpoints only
./dockavel source:test

این تست سریع فقط endpointهای فعلی داخل .env را بررسی می‌کند، preset را تغییر نمی‌دهد و برای قبل از pull/build سنگین در شبکه ناپایدار خیلی مفید است.

توضیح خطاها

خطاهای شبکه با عبارت‌های قابل فهمی مثل DNS resolution failed، TCP connection failed، timeout، TLS handshake failed، too many redirects، empty response و connection reset گزارش می‌شوند.

●
Diagnostics تعمیرکار خودکار نیست

Doctor و source:test هیچ تغییری در DNS، mirror، Docker config، container، profile یا hosts ایجاد نمی‌کنند.
