PROJECT MANAGER

Project-aware local development

Project Manager registers existing Laravel or Node.js applications, stores minimal metadata, generates Nginx routing, and keeps runtime choices tied to the project instead of your memory.

ADD · LIST · EDIT · REMOVErollback awaresource-safe
i
Project Manager does not create applications

The project directory must already exist inside projects/. Dockavel registers and routes it.

Add a project

bashregister
./dockavel project:add

The add flow detects Laravel from artisan plus composer.json, detects Node.js from package.json, and then asks only for settings that are relevant to the currently enabled Dockavel stack.

  • Project name and local domain
  • Database: none, MySQL or PostgreSQL when available
  • Redis usage when Redis is enabled
  • PHP runtime for Laravel, limited to enabled PHP profiles
  • Shared Node runtime for Laravel frontend commands when Node is enabled
  • Application port 3000-3099 for Node.js projects

Generated metadata

.dockavel.ymlLaravel example
version: 1
name: "my-api"
type: "laravel"
path: "my-api"
domain: "my-api.local"
php: "8.5"
database: "postgres"
redis: true
node: true

For Node.js projects, metadata stores the internal application port instead of a PHP version.

Generated Nginx config

Dockavel renders the existing Laravel or Node Nginx template, validates the full Nginx configuration and reloads Nginx when it is running. If validation or application fails, generated registration files are rolled back.

Edit a project

./dockavel project:editinteractive selection
./dockavel project:edit my-apidirect selection

You can change the project name, local domain, Laravel PHP runtime, database, Redis usage, shared Node usage, and Node application port. The project path and detected project type stay fixed.

↺
Edit is rollback-aware

Metadata and Nginx configuration are backed up before replacement. If Nginx validation or reload fails, the previous files are restored.

Remove a registration

./dockavel project:removeinteractive selection
./dockavel project:remove my-apidirect selection

Removal deletes only Dockavel registration files:

removedsource remains
projects/my-api/.dockavel.yml
nginx/conf.d/my-api.local.conf
✓
Project source is never deleted

projects/my-api/ remains intact. If Nginx application fails, the removed registration files are restored.

Hosts file

Dockavel intentionally does not edit the host machine's hosts file. It prints the entry you should add manually:

hostslocal domain
127.0.0.1 my-api.local

On Windows:

pathadministrator required
C:\Windows\System32\drivers\etc\hosts

Why metadata exists

The file is intentionally small. It is not another giant application configuration system; it stores only what Dockavel needs to route and manage the project. The planned command shortcuts will later use the same runtime mapping.

مدیریت پروژه

محیط local که پروژه را می‌شناسد

Project Manager پروژه Laravel یا Node.js موجود را ثبت می‌کند، metadata کوچک می‌سازد، Nginx routing را تولید می‌کند و runtime را به خود پروژه وصل نگه می‌دارد؛ نه به حافظه تو.

i
Project Manager پروژه جدید نمی‌سازد

پوشه پروژه باید از قبل داخل projects/ وجود داشته باشد. Dockavel فقط آن را register و route می‌کند.

اضافه کردن پروژه

bashregister
./dockavel project:add

برای Laravel وجود artisan و composer.json بررسی می‌شود و برای Node.js فایل package.json. بعد فقط گزینه‌هایی نمایش داده می‌شوند که با استک فعال فعلی معنی دارند.

  • نام پروژه و دامنه local
  • دیتابیس: none، MySQL یا PostgreSQL اگر فعال باشند
  • استفاده از Redis اگر Redis فعال باشد
  • PHP runtime برای Laravel، فقط از profileهای PHP فعال
  • Node مشترک برای commandهای frontend پروژه Laravel
  • پورت داخلی 3000-3099 برای پروژه Node.js

برای پروژه Node.js به‌جای PHP version، application port ذخیره می‌شود.

Nginx config تولیدشده

Dockavel template مناسب Laravel یا Node را render می‌کند، کل config Nginx را validate می‌کند و اگر Nginx در حال اجرا باشد reload انجام می‌دهد. اگر validation یا apply شکست بخورد، فایل‌های تولیدشده rollback می‌شوند.

فایل hosts

Dockavel عمداً hosts سیستم را خودکار ویرایش نمی‌کند. فقط entry لازم را چاپ می‌کند:

hostslocal domain
127.0.0.1 my-api.local

مسیر hosts در Windows:

pathadministrator required
C:\Windows\System32\drivers\etc\hosts

چرا metadata داریم؟

فایل عمداً کوچک است. هدف ساخت یک سیستم configuration بزرگ جدید نیست؛ فقط چیزهایی ذخیره می‌شوند که Dockavel برای route و مدیریت پروژه لازم دارد. shortcutهای آینده هم از همین mapping استفاده خواهند کرد.
